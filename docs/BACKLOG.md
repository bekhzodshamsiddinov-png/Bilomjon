# Development backlog
## P0 (before actual children use)
- Verify official curricula and school-language/academic-year mapping; secure lesson content rights.
- Gather teacher/parent research and learning goals; conduct ethics/privacy assessment.
- Complete user stories and acceptance tests per grade, subject, parent role.
- Implement parent-first signup, verified controls, data minimization and deletion policy.
- Establish educator review workflow, editorial content versioning and safeguarding red-team tests.

## P1 (MVP)
- Replace hardcoded demo with lesson API and approval-gated content DB.
- Add deterministic problem/answer checking and learner mastery rules.
- Implement guided non-generative tutoring where suitable; measure transfer learning.
- Build parental progress with real consented and securely stored events.
- Accessibility, low-end Android/browser testing, offline content caching.

## P2 (AI/voice)
- Benchmark Uzbek children's speech recognition, TTS and safety for different accents.
- Server-side constrained AI using retrieved approved lessons; structured response validation.
- Parent-controlled mic/session permissions, deletion policy and child voice retention avoidance.
- Safety incident response, human escalation, latency & per-lesson unit economics tests.

## P3 (pilot and launch)
- 30–50-family research pilot with baseline and follow-up assessments.
- Evaluate learning improvements, parent time and satisfaction, retention 2–4 weeks later.
- Expand subject coverage by educator signoff, not automatic generation alone.
- Pricing research, voluntary family subscription, localized payments, school partnerships.
